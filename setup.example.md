## Доступ по SSH

- Логин: `root`
- Пароль: сменён при первом входе, хранится только локально (не в этом файле)
- Настроен вход по SSH-ключу:
  - Приватный ключ: `~/.ssh/<имя_ключа>`
  - Публичный ключ: `~/.ssh/<имя_ключа>.pub`
  - Подключение: `ssh -i ~/.ssh/<имя_ключа> root@<IP_СЕРВЕРА>`
- Статус: ключ установлен, вход по паролю отключён (`/etc/ssh/sshd_config.d/99-key-only.conf`)

## Данные VPN-подключения

- Протокол: `<VLESS+TLS / VLESS+Reality / ...>`
- Inbound: `<remark>` (id=`<N>`), порт `<PORT>`, tag `<TAG>`
- Сертификат (если TLS без домена — Let's Encrypt на голый IP):
  - Профиль `shortlived` — обычные и ZeroSSL/аноним IP-сертификаты не выдают
  - Живёт ~7 дней, автопродление через `acme.sh` (cron)
  - При продлении перезапускает `x-ui` — новый сертификат подхватывается сам
  - Файлы на сервере: `/etc/x-ui/tls/<name>.crt` + `.key`
- Клиент: email `<email>`, UUID `<UUID_КЛИЕНТА>`, flow `<flow>`
- Fingerprint: `<fp>`, transport: `<network>`

### Ссылка для подключения

```
vless://<UUID_КЛИЕНТА>@<IP_СЕРВЕРА>:<PORT>?encryption=none&security=tls&flow=<flow>&fp=<fp>&type=tcp#<имя>
```

### Как выпускался сертификат (для справки)

1. Установлен `acme.sh`.
2. Если ZeroSSL (дефолтный CA) не даёт зарегистрировать аккаунт для IP-сертификата
   (`invalidContact`) — переключиться на `--server letsencrypt`.
3. Для IP-сертификатов у LE нужен отдельный ACME-профиль: `--cert-profile shortlived`.
4. Установить через `--install-cert` с `--reloadcmd "systemctl restart x-ui"`.

⚠️ **Грабля с автопродлением:** флаг `--cert-profile shortlived`, переданный только на
`--install-cert`, может не сохраниться в `Le_Certificate_Profile` конфига acme.sh — тогда
cron-продление уходит на дефолтный профиль и падает с `rejectedIdentifier` молча (если вывод
cron не перенаправлен в лог-файл). Передавай флаг сразу на `--issue`, и держи вывод cron в
файле (`/var/log/acme-renew.log`), не в `/dev/null` — иначе о падении узнаешь только когда
сертификат уже истёк.

### Как настраивалось (для справки)

Панель 3X-UI не даёт создавать подключения через SSH-консоль (`x-ui` CLI) — только через
веб-интерфейс. Программно (без браузера) — через REST API панели:

1. `GET /<секретный_путь>/` — получить CSRF-токен и сессионную куку.
2. `POST /<секретный_путь>/login` с логином/паролем и заголовком `X-CSRF-Token`.
3. `POST /<секретный_путь>/panel/api/inbounds/add` с JSON-описанием inbound, тем же заголовком.

Либо проще — Bearer-токен через `Authorization: Bearer <API_ТОКЕН>` на `/panel/api/...`,
без логина/CSRF (см. `add_inbound.py` в этом репозитории — там же выяснилось, что через этот
путь inbound реально работает, а прямая запись в sqlite-базу панели — нет).

## Заметки

- Некоторые хостеры троттлят новые TCP-подключения — SSH может зависать на обмене баннером;
  подождать ~10-20 сек и повторить.
- У панели 3X-UI встроена CSRF-защита для сессионных запросов — не бан по IP, просто нужен
  валидный токен со страницы логина.
- **Этот файл (после заполнения, как `setup.md`) не коммить и не пуш куда-либо публично** —
  он в `.gitignore` намеренно.
